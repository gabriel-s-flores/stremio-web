# T4.5 — Pointer mode (Magic Remote): plano de execução

**Estado em 28/09/2026:** T4.5 foi consolidada localmente em `webos` com T4.3/T4.4, a pedido do usuário. O trabalho original estava em `codex/t4.5-pointer-mode` (`06bb2f5e`) e foi integrado no commit `d661c25f`. Testes, lint, builds desktop/webOS normal/debug/packaged e compatibilidade ES2018 passaram na árvore integrada; runtime webOS/Chromium 68 continua pendente. O escopo segue o item T4.5 da página `~/stremio-memory/11 - Port webOS 5/Fase 4 — Navegação TV e Controle Remoto.md`. O evento nativo `cursorStateChange` informa `event.detail.visibility`; a LG documenta suporte desde webOS TV 2.x em [System UI Visibility](https://webostv.developer.lge.com/develop/guides/system-ui-visibility) e descreve a troca entre pointer e 5-way em [Magic Remote](https://webostv.developer.lge.com/develop/guides/magic-remote).

## Objetivo e decisão

Manter o Magic Remote operável nos dois modos de entrada do webOS 5. Pointer mode usa os eventos normais de hover/click já presentes no app. No 5-way, a navegação espacial e os anéis de foco existentes continuam ativos; o estado nativo de visibilidade controla somente o cursor CSS da página. A ausência de estado inicial conhecido não deve esconder o cursor.

A roda vertical mantém o scroll nativo em listas verticais. Ao passar sobre uma lista com overflow horizontal sem uma área vertical mais próxima, a roda avança essa lista horizontalmente. Só interceptar e cancelar o evento quando `scrollLeft` efetivamente mudar. Eventos de zoom (`ctrlKey`), áreas sem overflow e o scroll vertical nativo continuam sem interferência.

O build webOS mantém o cursor do DOM oculto enquanto a LG reportar cursor nativo invisível; ao voltar ao pointer mode, remove esse override. Não há cursor desenhado pela aplicação no checkout atual. O tratamento não altera `:hover`, `:focus`, `:focus-visible` ou o dispatcher de setas/OK.

## Leitura do checkout

- `PlatformProvider` já centraliza a integração webOS, e `webos/adapter.ts` registra os eventos de ciclo de vida no `document`.
- `src/App/styles.less` contém a base visual compartilhada. A regra de cursor precisa existir apenas no bundle webOS.
- As listas já declaram seus eixos roláveis, incluindo MetaRow horizontal e listas verticais de Settings, Addons, Player e modais. A maior parte da UI não precisa de listeners próprios.
- `Player.js` já usa `wheel` para volume quando nenhum menu está aberto. Esse ajuste precisa ignorar o evento somente se a rolagem horizontal o consumiu.
- `src/common/tv-focus.less` mantém o foco do 5-way independente da modalidade de ponteiro.

## Desenho implementado

1. **Estado LG:** o adapter escuta `cursorStateChange` em `document`, aceita somente `detail.visibility` booleano e publica mudanças válidas. `null` representa estado ainda desconhecido; callbacks repetidos não geram atualização.
2. **5-way e pointer:** `PlatformProvider` reflete o estado conhecido em `data-webos-cursor-visible`. A folha webOS oculta o cursor CSS na árvore do documento somente para o valor `false`; o valor `true` e o estado desconhecido não adicionam override.
3. **Scroll vertical:** permanece no mecanismo nativo de wheel do browser.
4. **Scroll horizontal:** um listener em captura encontra a primeira superfície rolável sob o ponteiro. `deltaX` move overflow horizontal; `deltaY` é convertido para movimento horizontal quando a primeira superfície rolável é horizontal. Delta em linhas/páginas é normalizado. O evento só é cancelado se a posição realmente mudar.
5. **Player:** sobre um alvo horizontal rolável, o listener de volume retorna sem alterar volume, inclusive no limite da lista. A roda fora de uma superfície horizontal continua seguindo o comportamento existente do Player.
6. **Escopo:** instalação do listener e regra CSS ficam restritas ao build webOS; desktop não recebe novas regras nem listeners.

## Matriz mínima de validação

| Estado/evento | Resultado exigido | Regressões a rejeitar |
|---|---|---|
| `cursorStateChange` com `visibility: true` | Estado pointer conhecido; cursor CSS não é suprimido | cursor continua escondido após a volta ao pointer |
| `cursorStateChange` com `visibility: false` | Cursor CSS da página oculto; foco 5-way segue visível | foco spatial removido ou controle deixa de responder a setas/OK |
| Evento ausente/malformado | Estado anterior preservado; estado inicial segue desconhecido | esconder cursor por inferência |
| Wheel sobre lista vertical | Scroll vertical nativo | listener converte para eixo horizontal ou consome o evento |
| Wheel vertical sobre MetaRow overflow-x | Lista move no eixo horizontal | roda alterada para volume, page scroll concorrente ou evento cancelado sem movimento |
| Wheel no limite da lista horizontal | Browser pode continuar o comportamento nativo | evento consumido sem mudança de scroll |
| Wheel sobre área sem lista | Player mantém o ajuste de volume existente | volume muda junto de um scroll de lista |
| Build desktop | Sem listener ou regra de cursor webOS | pointer/hover desktop alterado |
