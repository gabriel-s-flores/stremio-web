# T3.3 — Evidências da ponte `stremio-video`

> [!warning] Estado — 2026-09-09
> Contrato da ponte concluído com limitações explícitas. Player real hosted reproduziu mídia sintética no Chromium 68; fixture packaged selecionou os dois wrappers webOS. Isto não valida o app completo packaged nem reprodução por um streaming server remoto real. O console não ficou vazio: a atribuição dos erros está abaixo.

## Implementação e auditoria

- `src/common/Platform/videoPlatform.js`: helper puro `toVideoPlatform`, somente `webos → webOS`; os demais valores passam inalterados. `getVideoPlatformError` exige `window.webOS.service.request` como função para o alvo `webOS` e retorna erro crítico de código 10000, sem dados do stream.
- `src/routes/Player/Player.js`: usa o helper no valor enviado ao vídeo e conserva esse valor nas dependências do efeito. A guarda chama o `onError` existente (console e tela de erro crítico) e retorna antes de `video.load`. Não há downgrade.
- `useVideo.js` permaneceu inalterado: `implementationChanged` atualiza `state.manifest`, registra o nome no diagnóstico e propaga o evento. O probe observa essa função, delega à original e registra timestamp; não injeta um manifest.
- `device.ts`, `PlatformContext`, o vendor e o pacote instalado não foram alterados nesta tarefa. As alterações anteriores do checkout foram preservadas.
- O seletor real de `@stremio/stremio-video@0.0.96` compara `webOS` nos ramos URL e streaming server. `externalUrl` retorna null; YouTube preserva `YouTubeIFrameVideo`; shell tem precedência sobre URL/server. No emulador, `chrome.webview` está ausente, logo shell inativo. A indisponibilidade de Cast não impede seleção local.

HEAD: `4a440f3cd25ddeeab0d54e2ac466a33a62c1fdb8`, com checkout sujo. [Resumo e hashes SHA-256 das fontes/pacote/bundle](t33-summary.json) identificam o conteúdo além do commit.

## Runtime real — hosted

[Relatório final](t33-runtime-hosted.json), [log](t33-runtime-hosted.log), [dispositivo/firmware](t33-device.log).

- Emulador WEBOS5.0, SDK 5.0.0, firmware 02.00.30; Chromium 68.0.3440.106, V8 6.8.275.26, sem override de UA.
- Modo convidado confirmado por booleano, sem gravar perfil. Stream HTTP sintético de 30 s, gerado com FFmpeg `testsrc2`, H.264/yuv420p, 640×360/24 fps, sem áudio. Não foi usado catálogo pessoal.
- Player real em `#/player/<stream codificado>`, aberto via `window.core.encodeStream`, não a rota de menus `/debug/player`. Origem final do build: porta de teste 8094; mídia: porta 8093, via loopback do host visto pelo emulador.
- Antes da carga: contexto `webos`, API `service.request` presente, shell inativo, vendor primeiro na lista de scripts.
- Primeiro manifest observado: **`WebOsVideoWithHTMLSubtitlesWithVideoParams`**. Registro inclui timestamp e API presente. `readyState = 4`, tempo avançando acima de 1 s, `video.error = null`.
- Não houve exceção JS de inicialização nem erro crítico do Player na captura final. Isso não equivale a zero erro de console.

### Atribuição dos logs e limite de navegação

Os argumentos do console foram omitidos para evitar dados de sessão. Foram mantidos tipos, assinaturas estáticas e posições no bundle; as posições foram conferidas no bundle UTF-8 cujo hash consta no resumo:

1. Catch do registro de Service Worker (`SW registration failed`): limitação hosted HTTP/SW, T3.6.
2. Catch de `Chromecast`/`init-error`: Google Cast indisponível, não ativou o transporte de cast.
3. `tracksData.js` do pacote publicado consulta `http://127.0.0.1:11470/tracks/...`; a ausência desse serviço gera conexão recusada/`Failed to fetch`, tratada com `cb(false)`. O vídeo reproduziu; faixas/legendas e servidor remoto pertencem à Fase 5. Não foi aplicado patch em `node_modules`.
4. Uma rodada anterior navegou para fora do Player e expôs cleanup sem guarda em `src/routes/Player/useMediaSession.ts:96`: `navigator.mediaSession.setActionHandler` quando a API está ausente. [Captura anterior](t33-runtime-hosted-navigation-limit.json). Falha independente de navegação, não corrigida nesta ponte e não ocultada pela rodada final com carga de documento novo.

A interrupção da sessão deixou servidores Python antigos com respostas vazias; o servidor de mídia desta tarefa foi reiniciado e o build passou a ser servido na porta 8094. Também foi reaberto `ares-inspect`; essas falhas de infraestrutura foram resolvidas antes da captura final.

## Packaged — somente fixture dedicado

[Relatório](t33-runtime-packaged.json), [log](t33-runtime-packaged.log), [build](t33-fixture-build.log), [package](t33-package.log), [install](t33-install.log).

`tools/t33-video-fixture.js` usa `new Video()`, container DOM real e vendor nativo antes do bundle, sem core e sem mock de `window.webOS`. App dedicado `com.stremio.webos.t33.fixture`, executado em `file://`:

- URL direta: **`WebOsVideoWithHTMLSubtitlesWithVideoParams`**.
- Com `streamingServerURL`: **`WebOsVideoWithHTMLSubtitlesWithStreamingServer`**.
- Ambos observados por `implementationChanged`, com API presente antes do dispatch.
- O endpoint remoto é o servidor HTTP sintético, não um Stremio streaming server: APIs auxiliares de probe/hash retornam 404, incluindo uma rejeição não tratada. Esta evidência comprova seleção/instanciação, não reprodução remota completa ou ausência de erros nesse ramo.
- App completo packaged continua condicionado ao bootstrap WASM via `file://` já documentado em T3.1/T3.2; não foi revalidado como app completo. TV física não testada.

Para reproduzir: gerar a mídia sintética em `%TEMP%/stremio-t33-media/t33-test.mp4`, servir na porta 8093; executar `corepack pnpm exec webpack --config tools/t33-fixture.config.cjs`; empacotar `%TEMP%/stremio-t33-fixture`, instalar e lançar com `ares-*`. Os arquivos HTML/appinfo estão em `tools/t33-fixture*`. Abrir `ares-inspect` e passar sua porta a `node tools/t33-runtime.mjs hosted <CDP> <origem-hosted>` ou `node tools/t33-runtime.mjs packaged <CDP>`. O probe limpa entradas antigas do console antes da captura. Não foram necessários screenshots.
