# T3.8 — Links externos

Implementação concluída; aceite de abertura/retorno do navegador **pendente por limitação do emulador**.

## Implementação

- `resolveExternalUrl` preserva a whitelist e URLs permitidas, encapsula destinos não confiáveis no fragmento da página de warning e rejeita entradas inválidas.
- `Platform.openExternal` é o ponto de abertura. No webOS, o Adapter chama `webOS.service.request` → `luna://com.webos.applicationManager`, método `launch`, com `id: com.webos.app.browser` e `params.target` seguro. Não há fallback para `window.open`.
- `ExternalLink` conserva as propriedades nativas e callbacks no desktop. No webOS, cancela a navegação nativa e mantém o comportamento de teclado do Button. Settings e metadados escolhem Button para rotas `#...`.
- O modal global usa ModalDialog, TextInput somente leitura e `writeTextToClipboard`. Escape/Back fecha sem navegação e restaura o foco. O estado contém somente a URL resolvida, sem registro de URL em logs, Sentry ou analytics.
- Migrados Settings, Checkbox/Intro, menu, eventos, SharePrompt, IMDb/metadados, playlist e legendas. Configuração de addons e downloads imperativos de vídeo/legendas já usavam `platform.openExternal` e passam pelo novo Adapter. A lógica anterior de StreamsList permanece intacta.

## Emulador

Dispositivo `emulator`, `modelName: WEBOS5.0`, SDK `5.0.0`, firmware `02.00.30`.

As fixtures usam os componentes reais e o Adapter, sem iniciar o core. Foram instalados dois aplicativos isolados: `com.stremio.webos.t38.hosted` e `com.stremio.webos.t38.packaged`. Isso permite exercitar o seam também em `file://`, sem confundir o resultado com a restrição de WASM packaged já documentada nas tarefas anteriores. Não constitui validação do boot completo do core.

Resultados detalhados: [hosted](t38-runtime-hosted.json), [packaged](t38-runtime-packaged.json).

Em ambos os modos:

- Enter dispara uma única chamada com o payload correto.
- O destino não confiável é convertido em `https://www.stremio.com/warning#...` antes de alcançar o bridge.
- A falha nativa abre o modal com a URL segura completa; o input é somente leitura e selecionável integralmente.
- Clipboard indisponível é tratado pelo helper existente e produz feedback no modal, sem novo shim.
- Escape fecha, restaura foco e mantém o hash.
- A rota interna não chama o bridge.
- Ocultar/reabrir o app por meio da outra fixture gera `hidden → visible`, mantendo a rota e o estado montado. Esse ensaio de ciclo de vida usa outro app, **não o navegador**.

O Application Manager devolve a seguinte resposta ao lançamento real do navegador:

```json
{ "errorCode": -101, "returnValue": false, "errorText": "not exist" }
```

Portanto, abrir a URL permitida no navegador, carregar a página de warning nele e retornar do navegador **não foram aprovados**. A imagem instalada não contém `com.webos.app.browser`; não foi instalado um substituto nem simulado sucesso. É necessário repetir esses três casos num ambiente com o navegador LG disponível. TV física continua sendo validação adicional, conforme o escopo solicitado.

## Reprodução

O build `WEBOS_DEBUG` inclui a rota `#/debug/external-links`. A fixture isolada pode ser criada e instalada com:

```powershell
node tools/t38-build-fixture.cjs CAMINHO_NOVO
node tools/t36-http-server.mjs CAMINHO_NOVO 8099
node tools/t38-prepare.mjs http://10.0.2.2:8099 emulator CAMINHO_NOVO
ares-launch -d emulator com.stremio.webos.t38.hosted
ares-inspect -d emulator --app com.stremio.webos.t38.hosted
node tools/t38-runtime.mjs hosted ENDPOINT_CDP 8099
ares-launch -d emulator com.stremio.webos.t38.packaged
ares-inspect -d emulator --app com.stremio.webos.t38.packaged
node tools/t38-runtime.mjs packaged ENDPOINT_CDP com.stremio.webos.t38.packaged
```

O runner registra `acceptance: incomplete` quando o navegador está ausente, mesmo se as verificações do seam passam.
