## Implementação e auditoria

- `FileDropProvider` consulta `platform.isTV`. TV recebe o mesmo contrato `on/off`, com objeto estável e funções no-op; o componente ativo, com estado visual, input e efeitos de drag, não é montado. Desktop/mobile mantêm a implementação anterior.
- Discord permanece sem alteração: `shell.active` é o único critério. Testes incluem RPC habilitado no perfil e atividade solicitada, mesmo com shell inativo; não há subscrição, envio ou timer de retry.
- `UpdaterBanner` só assina `autoupdater-show-notif` e monta `UpdateBanner` com shell ativo. Instalação, fechamento, ocultação na rota Player e cleanup preservados.
- Menu e seção de atalhos exigem `!platform.isMobile && !platform.isTV`.
- Gates existentes de quit-on-close, fullscreen, hardware decoding, GPU, modo de vídeo e pause-on-minimize preservados e cobertos por controles positivos/negativos.
- Apple Login externo incluído no HTML somente com `!htmlWebpackPlugin.options.webos`.
- **“Abrir pasta de dados” não existe neste checkout.** A busca em Settings e Platform por abertura de pasta/diretório/dados encontrou exportação de dados via URL em General, não uma ação de abrir pasta local. Nenhuma funcionalidade nova foi criada.

Gamepad, atalhos globais, Chromecast, WebUpdateScreen/Service Worker (T3.6), hook e botões OAuth (T3.11) não foram alterados. A ajuda do controle remoto permanece na T4.12. O trabalho anterior do checkout foi preservado; nenhum reset ou limpeza foi realizado.

## Fixture isolada e runtime

[t310-build-fixture.cjs](../../tools/t310-build-fixture.cjs) compila FileDrop, Discord, UpdaterBanner, Settings, Menu, Interface, Player e Shortcuts reais com React 18. O harness substitui o contexto de plataforma/shell, perfil, dados de opções, tradução, detecção de rota e primitivas de apresentação. General, Streaming e Info são omitidos. Não substitui os gates testados. As chamadas de shell são registradas por spies; não há IPC real.

A mesma fixture é servida por HTTP local (hosted) e aberta por `file://` (packaged), representando os dois protocolos sem iniciar o core. A [auditoria da fixture](t310-fixture-artifact.json) comprova os componentes incluídos, ausência de módulos de core/WASM, compatibilidade ES2018 e hash do bundle. Ela não é um `.ipk` nem usa o bootstrap do app completo.

[t310-runtime.mjs](../../tools/t310-runtime.mjs) abre um browser headless com perfil temporário próprio e coleta via CDP. Cada protocolo passou **20/20 verificações**, incluindo montagem TV, eventos simulados, rerender, desmontagem, controle positivo desktop e nova montagem TV.

| Medida no cenário TV | Hosted HTTP | Packaged `file://` |
| --- | --- | --- |
| Listeners globais `drag*`/`drop` adicionados em `window` | 0 | 0 |
| Inputs de arquivo / overlays FileDrop | 0 / 0 | 0 / 0 |
| `on/off/send` de `discord-*` e `autoupdater-*` | 0 | 0 |
| Botão / seção de atalhos | 0 / 0 | 0 / 0 |
| Controles exclusivos de shell | 0 | 0 |
| Banner do updater de shell | Ausente | Ausente |
| Filhos do provider / controle Gamepad | Preservados | Preservados |
| Erros JS/CDP / `unhandledrejection` | 0 / 0 | 0 / 0 |

A contagem de drag mede os listeners globais usados pelo FileDrop; não conta a delegação interna de eventos do React no root. Os relatórios guardam os arrays brutos de subscrições/envios e erros, inclusive após cleanup/remount: [hosted](t310-runtime-hosted.json), [packaged](t310-runtime-packaged.json).

O controle desktop confirmou três listeners de drag, um input/overlay, ativação visual, os seis controles de shell e atalhos. Confirmou ainda `discord-connect`, `discord-set-activity`, notificação/instalação do updater, ocultação no Player e remoção de listeners ao desmontar. A entrega de arquivo e a remoção de consumidor são verificadas em Jest.

Durante a preparação, a fixture revelou duas falhas próprias: faltavam as constantes `VERSION`/`COMMIT_HASH` e o stub de estilos precisava tratar `__esModule`. Ambas foram corrigidas antes da coleta final. Os relatórios finais acima correspondem ao harness corrigido, com zero erros.

## Reprodução

```powershell
node tools/t310-checks.mjs
$fixturePath = Join-Path $env:TEMP ('stremio-t310-fixture-' + [guid]::NewGuid().ToString('N'))
node tools/t310-build-fixture.cjs $fixturePath
node tools/t310-runtime.mjs $fixturePath
```

O builder exige diretório novo; não limpa caminhos existentes. `T310_BROWSER` permite informar outro executável Chromium; por padrão usa o Edge instalado. O runner fecha apenas o browser e servidor que criou. Não usa sessão autenticada nem transmite dados de conta.

T3.10 pode ser marcada concluída com este aceite de componentes e artefatos. A comprovação em Chromium 68/emulador/TV física, a inicialização completa packaged e os fluxos das outras tarefas não são resultados desta execução.
